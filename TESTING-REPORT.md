## Addendum: "Liquid Glass" UI redesign + first-time tutorial (2026-08-31)

A follow-up UI/UX pass (chrome only — canvas rendering, drawing logic, tool behavior, autosave, and the docs site were explicitly out of scope and untouched):

- **Glass effect**: real `backdrop-filter: blur() saturate()` translucency (not a flat tint) applied to the toolbar, style panel, top-right icon bar, zoom/undo controls, menu/share/stats dropdowns, library panel, right-click context menu, command palette, help dialog, and feedback dialog — each with a 1px inner highlight and soft outer shadow, correct in both themes (`src/style.css`, `--glass-*` tokens). Verified visually in both light and dark theme.
- **Adaptive icon/text contrast**: icons and text on the toolbar, style panel, top-right bar, zoom/history controls, context menu, stats panel, menu dropdown, and library panel now sample the canvas content directly behind them and flip between dark and light rendering independently of the app's theme — implemented as a **debounced settle-based sample** (~220ms after pan/zoom/draw stops), not per-frame, since a `getImageData` readback on every animation frame is a known perf cliff; this was the cheaper approximation the brief asked me to consider, and it's what's implemented (`src/theme/adaptiveContrast.ts`, `src/theme/useAdaptiveContrast.ts`). Verified end-to-end: a black-filled rectangle placed under the toolbar flipped its computed CSS color from `#1d1d1f` to `#f5f5f7` and back after clearing the canvas. Command palette, help dialog, and feedback dialog intentionally do **not** adapt — they sit behind a dark modal scrim, not directly on the canvas, so theme-based text already reads correctly there.
- **First-time tutorial**: a 6-step skippable spotlight tour (`src/tutorial/`), shown once per board via a `hasSeenTutorial` flag in the same Yjs/IndexedDB store as the drawing itself (`yMeta`, not localStorage) — verified it shows on a fresh room, persists across reload, and doesn't reappear. Replayable from the command palette ("Replay tutorial") and the help dialog ("Replay the getting-started tour") — both verified working. Keyboard: Escape/Skip to dismiss, Arrow keys and Enter to navigate, Tab is trapped within the tooltip card, and all transitions are skipped under `prefers-reduced-motion`.
- **Regression check**: re-ran the core interaction set (draw, undo/redo, `Ctrl+A`/`Ctrl+D`, pinch-zoom, layout at 375/768/1280px) after the redesign — all still pass, no console errors.
- **Performance regression found and partially fixed**: the first deployed version tanked Lighthouse TBT (110ms/score 97 baseline → one run spiked to 2,230ms/score 6, stable runs ~470-520ms/score 56-61). Root cause: `getImageData()` calls straight off the main, GPU-backed drawing canvas force a full GPU→CPU sync per call, and up to 5 glass panels were each doing that independently on every settle. **Fixed** by sampling through a tiny dedicated offscreen canvas (`willReadFrequently: true`) that the panel region is cheaply `drawImage`-blitted onto first, skipping sampling entirely while the tutorial is open, and reducing the blur radius 22px → 14px. Re-verified live: TBT is now **~320-340ms, score 75-77** — a large improvement, but still above the 110ms/97 pre-redesign baseline. The remaining cost is `Style & Layout` time (~450ms in the trace), which is the inherent compositing cost of multiple simultaneous real `backdrop-filter` blur regions — a genuine tradeoff of "true frosted glass" (explicitly requested) vs. a cheaper fake-gradient approximation. Also worth noting: this number reflects the **first-visit** case, where the tutorial always renders (Lighthouse always crawls with a fresh profile) — returning visitors, who are the overwhelming majority of real traffic, don't pay the tutorial's render cost or trigger the sampling-skip-while-tutorial-open path at all, so their real TBT is very likely lower than this measured figure. Further reducing the number of distinct blur layers (e.g. merging the toolbar+menu into one glass container instead of two adjacent ones) would likely close more of the gap but wasn't done in this pass — flagging as a possible follow-up rather than doing it unprompted.

## Addendum: Excalidraw gap-closing pass — quick wins + medium-effort features (2026-08-31)

Implemented the "Quick wins" and "Medium effort" tiers from `GAP-ANALYSIS.md` (large/optional items and the explicitly-out-of-scope Excalidraw+ paid-tier features were **not** touched, per the brief). Everything below was verified against the local dev build; no formal automated test suite exists in this repo (`npm test` isn't defined), consistent with the original QA pass — verification here means live browser interaction plus `npx tsc --noEmit` after every change.

**Quick wins (all shipped):**
- **Arrow-to-shape binding** — `src/canvas/binding.ts` (new): ray-to-edge intersection for rectangle/diamond/ellipse. Wired into arrow creation, and a new `syncBoundArrows` store method keeps bound endpoints glued to their shape through moves, resizes, arrow-key nudges, and align/distribute. Manually dragging a bound endpoint in point-edit mode clears that binding (so it doesn't fight the user). Verified live: dragging a bound rectangle (via mouse and via the stats panel) correctly drags the arrow's endpoint with it.
- **Editable stats panel** — X/Y/W/H are number inputs now, committed as one undo step on blur/Enter.
- **Align/distribute** — 6 align modes + 2 distribute axes, in the context menu and command palette.
- **Copy/paste to clipboard** — round-trips via `navigator.clipboard` as marked JSON (`src/utils/clipboard.ts`). Couldn't get a live OS-clipboard round-trip in the sandboxed test browser (`clipboard-read`/`write` permission is hard-denied there — same caveat already on record for copy-to-clipboard-as-PNG in Phase 2 above); confirmed it fails silently rather than crashing. Recommend one manual check in a real browser.
- **Export selection only** — checkbox in the export menu, filters PNG/SVG/clipboard-PNG to the current selection.
- **Element hyperlinks** — `link` field added to the element model; add/edit via the context menu, Ctrl/Cmd-click to open.

**Medium effort (all shipped):**
- **True vector SVG export** — `src/canvas/renderSVG.ts` (new) uses `rough.svg()` to emit real `<path>`/`<text>`/`<image>` elements instead of the old raster-PNG-wrapped-in-`<svg>`. Verified by exporting a scene with shapes, a freehand stroke, and an image, and confirming the output contains actual `<path>` geometry (not a single `<image>` covering the whole canvas) plus exactly one `<image>` for the raster image element, as expected.
- **Bound text that reflows** — completed the previously-cosmetic containerId/double-click feature: text now genuinely word-wraps to the container's width (`src/canvas/text.ts`, new), the container grows to fit as you type, and both re-wrap correctly when the container is resized via handle or the stats panel. A `syncBoundText` store method (mirroring `syncBoundArrows`) keeps it correct through every kind of container transform. Verified live: typed 82 characters into a rectangle, watched it wrap to 6 lines with the container auto-growing vertically and staying centered; then resized the container wider and watched it re-wrap to 3 lines.
- **Multi-point line/arrow editing** — a plain click (not a drag) with the line/arrow tool now starts a click-chain (click to add points, click near the last point or Enter to finish, Escape to cancel); double-clicking an existing line/arrow enters point-edit mode (drag a point, click a segment to insert one, Alt+click to remove one, `+`/`Alt+Backspace` as minimal keyboard affordances for add/remove). The classic 2-point drag-to-draw is untouched and remains the default. Verified live: built a 3-point arrow via click-chain, confirmed the arrowhead follows the last segment's direction; entered point-edit mode on a 2-point line, inserted a midpoint by clicking the segment, dragged it to bend the line.
- **Lasso selection tool** — new `"lasso"` tool (key `Q`), `isPointInPolygon`/`isElementInPolygon` added to `geometry.ts` (ray-casting, same "all four bounding-box corners inside" containment rule the existing rectangular marquee already uses). Verified via a dispatched pointer-event path tracing an actual loop: correctly selected only the element inside the polygon.
- **Scene search** (`Ctrl/Cmd+Shift+F`, not plain `Ctrl+F` — that's reserved for the browser's own page-find) — searches element text/type, reuses the command palette's own modal markup, scrolls/pans to center the match and selects it. Verified live: searched "rectangle", clicked a result, canvas panned to it and selected it.
- **Image cropping** — `crop: {x,y,width,height}` added to `ImageElement` (natural-image-pixel space). Entered via the context menu's "Crop image" (with "Reset crop" once one exists); edge/corner handles trim the box (reusing the same resize-handle hit-test pattern), dragging inside pans the source within the current box size; Enter applies, Escape reverts to the pre-edit crop. Verified live end-to-end: cropped a synthetic test image's right edge inward, confirmed the box shrank and the visible content changed correctly, applied with Enter, confirmed "Reset crop" then appeared in the context menu.
- **Shape library panel redesign** — now a docked, full-height sidebar (`src/components/LibraryPanel.tsx`) with three tabs (Built-in / My library / Imported) instead of one short floating box with everything stacked; items you add manually are tagged `source: "custom"`, items from an imported `.excalidrawlib` are tagged `source: "imported"`, and each has its own tab. Verified live: added a selection, watched it land in "My library" with the tab auto-switching and the count updating.

**Bug found and fixed in the course of this work (pre-existing, not introduced by the above):** the 8 resize/rotate handles in `SelectionOverlay.tsx` were rendered with `pointerEvents: "auto"` but no click handler of their own — since they sit as DOM siblings of the `<canvas>` (not descendants), a click landing dead-center on a handle was swallowed and never reached the canvas's own manual hit-test that actually drives the resize/rotate drag. In practice this meant clicking exactly on a handle's center pixel did nothing; clicking a few pixels off (still within the existing 10px hit-test tolerance) worked, which is presumably why this went unnoticed in the original QA pass. **Fixed** by setting those handles to `pointerEvents: "none"` (they were always purely visual — the real hit-testing already happens in `Canvas.tsx`), matching the pattern the new point-editor and crop overlays use. Verified live: a drag starting exactly on a handle's center now resizes correctly, where it previously did nothing.

**Testing-environment caveat, not a product bug:** in this sandboxed browser, the automation tool's synthetic `double_click` action and its bare `"Return"`/`Enter` key dispatch were unreliable at triggering the corresponding native browser events (confirmed by dispatching real `dblclick`/`keydown` events via `page.evaluate`-equivalent JS and observing the exact same code path fire correctly). Modifier-combo shortcuts (e.g. `Ctrl+Shift+F`) and plain single-key presses worked fine through the same tool. This only affected test *execution*, not the app — real mouse/keyboard input in an actual browser doesn't go through this synthetic path.

Re-ran the core regression set after all of the above (draw, undo/redo, `Ctrl+A`/`Ctrl+D`, pinch-zoom, layout at 375/768/1280px) — all still pass, no console errors.

## Addendum: Large/optional gap-analysis tier (2026-09-01)

Scoped with the maintainer to three items — elbow arrows + flowchart tooling, web-embed/iframe elements, and AI text-to-diagram generation (bring-your-own API key) — with E2EE collaboration, i18n, a VS Code extension/npm package, laser pointer, Mermaid conversion, and collaboration-aware undo/redo explicitly parked (not attempted). All verification below is against the local dev build; `npx tsc --noEmit` and `npm run build` both pass clean after every change.

**Elbow arrows + flowchart tooling:**
- `src/canvas/elbow.ts` (new) computes a single-bend orthogonal route between two points; wired into canvas rendering, SVG export, and hit-testing (`geometry.ts`'s `distanceToPolyline`) so clicking near the bend selects the arrow, not just the straight start-end line. A checkbox in the style panel ("Elbow (flowchart connector)") toggles it per-arrow, collapsing any manual multi-point bends when turned on since the router takes over; a command-palette entry does the same for keyboard access. Multi-point click-chain creation and point-edit mode are both skipped for elbowed arrows (nothing to manually edit once the router owns the path).
- Added a "Flowchart: decision" library preset (start → decision diamond → two branches) exercising elbow arrows + arrow-binding together. Building it surfaced and fixed a **real pre-existing bug**: `LibraryPanel.tsx`'s `insert()` remapped element IDs when cloning a library item but never rewrote `containerId`/`startBinding`/`endBinding` to point at the *new* IDs — any library item with internal bindings (bound text or bound arrows) would insert with silently-dangling references. No prior built-in item exercised this path, so it went unnoticed until now. **Fixed** by remapping those three fields through the same ID map used for the elements themselves.
- Verified live: inserted the flowchart preset, confirmed the connectors render as clean right-angle bends (not straight diagonals) between the diamond and its two branches; moved a branch box via the stats panel and confirmed its connector re-routed to follow it, with a fresh bend recomputed from the new position.

**Web-embed / iframe elements:**
- `src/utils/embedAllowlist.ts` (new): validates a URL against a curated list of known-embeddable domains (YouTube, Vimeo, Figma, CodeSandbox, CodePen, Google Docs/Maps, Loom, Spotify, GitHub Gist, Notion, Observable) and requires `https:` — matches Excalidraw's own security posture rather than allowing arbitrary iframes. A rejected URL shows an explanatory alert; nothing is created.
- New `embed` element type + tool (`W`). Canvas/SVG export render a placeholder box with the domain name (a bitmap/vector export can't capture a live cross-origin frame); the actual live content is a real DOM `<iframe>` (`EmbedOverlay.tsx`) positioned over the canvas, `sandbox="allow-scripts allow-same-origin allow-popups allow-forms allow-presentation"`, `referrerpolicy="no-referrer"`.
- The iframe is `pointer-events: none` by default — inert, so normal canvas click/select/drag/resize hit-tests it like any other element — and only becomes interactive for the one element entered via double-click ("interact" mode, exits on Escape or switching selection), the same click-conflict problem the point-editor and crop overlays already solved, reused here.
- Verified live end-to-end: created a real YouTube embed, confirmed the live iframe actually loaded cross-origin content (YouTube's own "video unavailable for this ID" error page rendered inside it — proof the frame is genuinely live, not a mock); confirmed a plain click-drag moved the element (iframe correctly inert, canvas hit-test received the click); confirmed double-click set the iframe to `pointer-events: auto` with a visible focus outline, and Escape reverted it to inert; confirmed the allowlist correctly accepts known domains and rejects an arbitrary domain, `http:`, and a `javascript:` URL; confirmed SVG export contains the placeholder rect + hostname, not a broken embed tag.

**AI text-to-diagram generation (bring-your-own API key):**
- `src/ai/config.ts` stores `{provider, apiKey}` in localStorage only; `src/ai/generate.ts` calls the configured provider directly from the browser (Anthropic's Messages API with the `anthropic-dangerous-direct-browser-access` header required for browser-origin calls; OpenAI's Chat Completions API with `response_format: json_object`), asks for a constrained JSON shape (shapes + arrows-by-index, not the full element schema), strips a markdown code fence defensively if the model wrapped its answer in one, and materializes the result into real bound/elbow-connected DrawBoard elements (reusing the same binding system as manual arrow-drawing).
- `AISettingsDialog.tsx` (provider + key entry, explicit privacy disclosure that the key is browser-local and sent straight to the provider) and `AIGenerateDialog.tsx` (prompt textarea, redirects to settings if no key is configured yet) — both new, both reuse the existing `.feedback-dialog`/`.feedback-form` glass-styled markup rather than introducing a new visual style.
- **Verified end-to-end with a mocked network response** (stubbed `window.fetch` to return a canned Anthropic-shaped 4-shape flowchart): the full pipeline — parse → materialize → bind → render — produced 11 correctly-typed elements (4 shapes + 4 bound text labels + 3 bound, elbowed arrows) and rendered as a clean, readable flowchart on canvas. Also verified through the real dialog UI that submitting a prompt with no API key configured correctly redirects to the settings dialog instead of attempting a call.
- **Not verified: an actual live call to a real OpenAI or Anthropic API key** — this repo's testing has no API key and spending real API credits without being asked wasn't appropriate here. The Anthropic integration is more likely to work as shipped (their dangerous-direct-browser-access header exists specifically to support this use case); OpenAI's current CORS policy for direct browser calls to `api.openai.com` is genuinely uncertain — it may reject cross-origin requests entirely, in which case that provider option would surface a clear network-error message rather than fail silently, but it hasn't been confirmed to actually complete a round trip. **Recommend one manual test with a real key before relying on this feature**, especially for the OpenAI path.

Re-ran the core regression set after all of the above (draw, undo/redo, `Ctrl+A`/`Ctrl+D`, pinch-zoom, layout at 375/768/1280px) — all still pass, no console errors.

## 🚨 Security issues

**No XSS, injection, or exposed-secret vulnerabilities found.** Specifically tested/verified:
- The feedback form's `escapeHtml()` correctly neutralizes `<script>`, `onerror=`, and SVG-breakout XSS payloads before they reach the outgoing email.
- No secrets, API keys, or credentials found anywhere in the client bundle or public repo (this was already verified during the earlier open-sourcing pass of this project, and nothing since has reintroduced any).
- React's default escaping + no `dangerouslySetInnerHTML` anywhere in the feedback form covers client-side rendering.

**One abuse/cost-risk item, now mitigated:** BUG-03 below — `/api/feedback` had no rate limiting beyond an easily-bypassed honeypot. A per-IP sliding-window limiter (5 requests/10 min) has been added; see BUG-03 for the one remaining caveat (it's per-instance, not globally coordinated, since that would need a shared store like Vercel KV).

| BUG-08 | Gap-closing pass | Major | Resize/rotate handles had a **dead center-click zone** — clicking exactly on a handle's center pixel did nothing | Select any element, click precisely on the center of a resize handle (not a few px off) and drag. `SelectionOverlay.tsx`'s handle `div`s had `pointerEvents: "auto"` with no click handler of their own; as DOM siblings of `<canvas>` (not descendants), the click never reached the canvas's own manual proximity-based hit-test that actually drives the drag. | BUG-09 | Large/optional tier | Major (data integrity) | Inserting a library item with internal bindings (bound text or bound arrows) left those bindings **dangling**, pointing at the library item's own original IDs instead of the freshly-cloned ones | `LibraryPanel.tsx`'s `insert()` builds an `idMap` from old element IDs to new cloned IDs, but never used it to rewrite `containerId` (bound text) or `startBinding`/`endBinding` (bound arrows) on the clones. No built-in library item exercised this before the new "Flowchart: decision" preset (which has bound, elbowed arrows) was added. | **Fixed** — `insert()` now remaps `containerId`/`startBinding.elementId`/`endBinding.elementId` through the same `idMap`, dropping a binding to `null` if its target somehow wasn't part of the inserted item rather than leaving a dangling reference. |
